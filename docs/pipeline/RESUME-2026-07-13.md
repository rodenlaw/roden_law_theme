## ES twin publish mechanics (NOT in the pipeline repo — do it manually)

`publish.mjs` has no locale support. The working recipe (used for 5004/5010, matches the 7/7 cycle):
1. ES draft frontmatter: `target_url: /es/blog/es-<en-slug>/` (the `es-` prefix becomes the WP slug), `locale: es`.
2. `publish.mjs --run <id> --cluster N --draft <draft-N-es.md> --prod` (QA gate is EN-pattern — expect Spanish false-fails on last_reviewed/key_takeaways/faq/stat_citations; verify Última revisión / Puntos Clave / Según / **P:**/**R:** manually).
3. Link over SSH: `wp post meta update <ES id> _roden_locale es`, `wp post meta update <ES id> _roden_translation_of <EN id>`, `wp post meta update <EN id> _roden_translation_es <ES id>`.
4. `stage6.mjs --run <id> --cluster N --prod` flips it live. Canonical ES URL = `/es/blog/<en-slug>/` (theme rewrite; the raw `/blog/es-<slug>/` 301s to it).
5. Snapshot `state.json`/`qa-report-N.json`/`gbp-N.json` before the ES publish (it overwrites the EN `publish_*` keys), then restore EN into `publish_*` and move ES values to `publish_es_*` — see the fixed-up state.json in either completed run for the exact shape.
